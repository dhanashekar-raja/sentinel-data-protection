
# Documentation Contribution Guidelines

Thank you for contributing to Sentinel Data Protection documentation.

## 1. Contribution Workflow

All documentation changes must follow the Git-based contribution workflow.

1. Synchronise your local main branch.
2. Create a feature branch.
3. Make the required documentation changes.
4. Review the Markdown content.
5. Commit your changes.
6. Push the feature branch.
7. Submit a pull request for review.

## 2. Branch Naming Convention

Use descriptive branch names.

Examples:

- feature/installation-update
- feature/configuration-guide
- fix/broken-documentation-link
- docs/release-notes-update

## 3. Commit Message Guidelines

Use descriptive commit messages with appropriate prefixes.

Examples:

- docs: add installation guide
- docs: update configuration instructions
- fix: correct broken documentation link

## 4. Documentation Standards

All documentation contributions must:

- Use clear and concise language.
- Follow the existing Markdown structure.
- Use descriptive headings.
- Include meaningful link text.
- Provide alternative text for images.
- Use appropriate notes and warnings.
- Maintain consistent product terminology.

## 5. Pull Request Requirements

Every pull request should include:

- A meaningful title.
- A summary of the changes.
- A list of modified documentation topics.
- Review confirmation.
- Any relevant testing information.

## 6. Review and Approval

Documentation changes must be reviewed before they are merged into the main branch.

Reviewers should verify technical accuracy, content quality, formatting, and navigation.

## 7. Conflict Resolution

Contributors must investigate conflicting changes and confirm the correct product information with the relevant subject-matter expert before resolving documentation conflicts.
